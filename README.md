## `01` · The fallen-angel protocol

I build tools that stay understandable after the magic wears off. That usually means local-first execution, explicit boundaries, explainable decisions, deterministic tests, and interfaces that show their work instead of hiding it behind a black box.

The aesthetic is celestial cyberpunk; the engineering philosophy is practical: **keep the signal, cut the noise, ship the useful thing.**

## `05` · How I build

**Local first.** If a feature can run on the user's machine, I want that path to be real, documented, and useful. Cloud calls should be explicit rather than assumed.

**Boundaries before spectacle.** A system is stronger when its scope, policy, evidence, and failure modes are visible. I like tools that can explain what they did and what they deliberately refused to do.

**Small surfaces, deep utility.** I would rather ship one sharp CLI, parser, router, or dashboard than a giant abstraction that nobody can inspect. The goal is not to look intelligent; it is to make the next decision easier.
